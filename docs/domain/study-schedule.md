# Study Schedule Domain

The schedule domain lives in `src/lib/domain/schedule` and is the only source for civil-date operations, weekly availability and initial schedule generation.

## Example

With a start on `2026-06-11` and the default availability:

```ts
import {
  DEFAULT_WEEKDAY_AVAILABILITY,
  PRODUCT_TIMEZONE,
  buildStudySchedule,
  parseCalendarDate,
} from "@/lib/domain/schedule";

const schedule = buildStudySchedule(plan, {
  startDate: parseCalendarDate("2026-06-11"),
  timezone: PRODUCT_TIMEZONE,
  weekdayAvailability: DEFAULT_WEEKDAY_AVAILABILITY,
});
```

Expected result for five sequential days:

| Plan Day | Date       | Real day      | Note      |
| -------- | ---------- | ------------- | --------- |
| 1        | 2026-06-11 | Thursday      | study     |
| 2        | 2026-06-12 | Friday        | study     |
| 3        | 2026-06-13 | Saturday      | 240 min   |
| —        | 2026-06-14 | Sunday        | rest      |
| 4        | 2026-06-15 | Monday        | study     |
| 5        | 2026-06-16 | Tuesday       | study     |

## Main contracts

- `CalendarDate`: a civil date validated in the `YYYY-MM-DD` format.
- `WeekdayAvailability`: availability configurable per real day of the week.
- `StudyPlan`: a minimal sequential plan.
- `ScheduledStudyDay`: a chronological day generated by the scheduler.

## Rules

- The real date determines the day of the week.
- Disabled days don't consume content.
- Rest days appear in the schedule with no items.
- Each `StudyPlanDay` occupies one enabled date.
- Blocks are not split silently.
- Days above capacity get `capacityStatus: "over_capacity"`.
- The domain doesn't compute progress and doesn't figure out "today" on its own.

## Querying

Use `schedule-selectors.ts` to fetch days, the next study, the previous study, a range and weekly grouping. Visual weeks start on Monday and end on Sunday.
